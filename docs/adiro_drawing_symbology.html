Description

  • Cross-discipline layout content. Generic symbol classes like dimensions, reference symbols, grids, etc. (mostly reusable non-domain symbols). All symbols are subclasses of DrawingElement from the drawing metadata ontology.

  • The symbols and marks a drawing uses, shared by every discipline: reusable symbols and text that appear across disciplines, such as dimensions, grids, levels and references to another layout or drawing: the graphical reference symbol, the inline and standalone reference expressions, and the occurrences of drawing and layout identifiers they are made of. Every one is a kind of drawing element from the drawing-metadata module. The discipline modules build on them.

Drawing identifier mention c

IRI https://w3id.org/adiro/adiro_drawing_symbology#DrawingIdentifierMention
Description

One evidenced occurrence of drawing-identifier (sheet-identifier) text on a source drawing, distinct from the DrawingSheet that the text may denote. Source-text evidence and an immutable source identity are admission requirements for exported UC-03 mentions. Precise localisation is required for navigation, not for an independently accepted sheet resolution: an unlocalisable text block may retain its accepted denotesDrawingSheet edge without a fabricated bounding box or clickable link. Unresolved candidates remain in extraction evidence; no geometry cardinality axiom is imposed.
Sub Class Of admeta:DrawingElement
In Domain Of denotesDrawingSheet op
Super Class Of Standalone Drawing Reference c

Layout identifier mention c

IRI https://w3id.org/adiro/adiro_drawing_symbology#LayoutIdentifierMention
Description

One evidenced occurrence of layout-identifier text (a small integer or letter), distinct from a target Layout. A complete inline reference may contain several such occurrences, attached with contains; no target is inferred from matching text alone.
Sub Class Of admeta:DrawingElement

Inline Layout and Drawing Reference c

IRI https://w3id.org/adiro/adiro_drawing_symbology#InlineLayoutDrawingReference
Description

A complete inline textual expression relating layout number(s) to a sheet number, such as '1, 3, 5 & 7/S601'. The component mentions retain their own identities; accepted Layout targets are connected separately by inlineReferencesLayout. Expected composition: one sheet-identifier mention and at least one layout-identifier mention, attached with contains; this is checked as an application-profile condition, not asserted as an OWL restriction.
Sub Class Of Reference expression c
In Domain Of inlineReferencesLayout op

Standalone Drawing Reference c

IRI https://w3id.org/adiro/adiro_drawing_symbology#StandaloneDrawingReference
Description

A drawing-identifier occurrence that itself constitutes a complete reference. One individual is both the DrawingIdentifierMention and the ReferenceExpression: no duplicate wrapper, self-directed hasDrawingIdentifierMention edge or second geometry is needed. An ungrouped mention is not automatically standalone merely because its parent has not been identified.
Sub Class Of
  • Drawing identifier mention c
  • Reference expression c

ReferenceSymbol c

IRI https://w3id.org/adiro/adiro_drawing_symbology#ReferenceSymbol
Description

A symbol drawn on a Layout that references another Layout (on the same or a different DrawingSheet). Replaces the earlier Callout class. Typical instances include Detail Markers, Section Markers, and Elevation Markers. The marker type is not modelled — it is derivable from the target Layout's LayoutContentType.
Sub Class Of Reference expression c
In Domain Of referencesLayout op
In Range Of hasReferenceSymbol op

Object Properties

denotesDrawingSheet op

IRI https://w3id.org/adiro/adiro_drawing_symbology#denotesDrawingSheet
Definition

The DrawingSheet that one occurrence of a drawing number on a drawing has been accepted as naming.
Comment

It does not assert that a Layout target or an output-PDF navigation link was resolved. A mention is expected to have at most one accepted sheet; this is an application-profile condition, not an OWL functional axiom, because a functional axiom would make a reasoner merge two sheets instead of reporting the conflict.
Domain Drawing identifier mention c
Range admeta:DrawingSheet

inlineReferencesLayout op

IRI https://w3id.org/adiro/adiro_drawing_symbology#inlineReferencesLayout
Definition

An accepted target Layout of an inline reference to layouts and a drawing.
Comment

Multiple supported targets may be asserted; unresolved members do not acquire target edges.
Domain Inline Layout and Drawing Reference c
Range admeta:Layout

hasReferenceSymbol op

IRI https://w3id.org/adiro/adiro_drawing_symbology#hasReferenceSymbol
Description

A Layout contains one or more ReferenceSymbols. To navigate from a symbol back to the Layout it is drawn on, use the SPARQL inverse path ^adsym:hasReferenceSymbol - ADIRO declares no named inverse properties and no owl:inverseOf axioms (see GitHub issue #21).
Sub Property Of admeta:contains
Domain admeta:Layout
Range ReferenceSymbol c

referencesLayout op

IRI https://w3id.org/adiro/adiro_drawing_symbology#referencesLayout
Description

Target Layout — the Layout this ReferenceSymbol points to. The target is Layout-level, not DrawingSheet-level. To find the symbols pointing AT a Layout, use the SPARQL inverse path ^adsym:referencesLayout - ADIRO declares no named inverse properties and no owl:inverseOf axioms (see GitHub issue #21).
Domain ReferenceSymbol c
Range admeta:Layout
