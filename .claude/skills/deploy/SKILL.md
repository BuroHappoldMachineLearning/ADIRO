# ADIRO — docs build, validation & publishing

**Source of truth:** the CI files in this repo (`.github/workflows/`, `mkdocs.yml`, `pyproject.toml`).
If this skill and the CI disagree, the CI wins — fix this skill.

## What ships and how
Material-for-MkDocs static site -> GitHub Pages at https://burohappoldmachinelearning.github.io/ADIRO/.
- Deploy workflow: `.github/workflows/generate-deploy-docs.yml` (triggers on push to `main`/`master` + manual `workflow_dispatch`). Jobs: `validate` + `test-ttl2md` + `test-docs` -> `generate-docs` -> `deploy`.
- Docs are generated by `scripts/generate_docs.py`: reads every `src/*.ttl`, emits a pyLODE HTML page per ontology, native Markdown pages (via the in-repo `ttl2md/` package) into `docs/ontologies/`, copies `.ttl` + `*.display.json` into `docs/`, and regenerates `docs/index.md`. CI commits the regenerated `docs/` back, then runs `mkdocs build` (output `site/`, git-ignored) and deploys the artifact.
- Local (uses `uv`): `uv sync`; `uv run python scripts/generate_docs.py`; `uv run mkdocs serve` (preview at http://127.0.0.1:8000/ADIRO/) or `uv run mkdocs build`.

## Validation & sync CI
- `.github/workflows/validate-ontology.yml` — on PRs to any branch; runs `scripts/validate_ontology.py` over `src/*.ttl` (parse check, circular-subclass detection, ensures an `owl:Ontology` declaration). Same validate step also gates the deploy workflow.
- `.github/workflows/sync-issues-to-youtrack.yml` — one-way mirror GitHub issue events -> YouTrack RES project via `scripts/sync_issue_to_youtrack.py` (inbox model, YouTrack is never pushed back). `.github/workflows/backfill-issues-to-youtrack.yml` — manual one-shot backfill (`dry_run` default true), idempotent via a youtrack-id marker comment.

## Versioning
Per-module SemVer: each `src/*.ttl` carries its own `owl:versionIRI` (versioned IRI) + `owl:versionInfo` string, versioned independently (currently metadata 2.0.0, others 1.0.0). On a GitHub **release**, `.github/workflows/backup-version.yml` snapshots `src/*.ttl` into `versions/<tag>/`. See KB DATA-A-10 for the architecture; RES-27 for status — **do NOT make TBox `.ttl` edits until versioning is ratified.**

## Gotchas
- Ontology sources live in `src/` (4 modules: `aec_drawing_metadata`, `aec_common_symbols`, `aec_domain_common`, `aec_facade_domain`); docs pipeline hard-codes a dependency sort order in `generate_docs.py`.
- Pins: `pylode==3.2.3`, `rdflib>=6.0.0`, `mkdocs-material>=9.5.0`, Python 3.10–3.13 (CI uses 3.12). `ttl2md/` is a separate package imported from its `src/` tree, with its own tests (`test-ttl2md` job).
- `docs/brainstorming|modularization|governance/` are excluded from the built site (`exclude_docs` in `mkdocs.yml`) — verify before assuming a docs page publishes.
- No secrets here: YouTrack sync uses `secrets.YOUTRACK_URL/TOKEN` + `vars.*` from repo settings.
