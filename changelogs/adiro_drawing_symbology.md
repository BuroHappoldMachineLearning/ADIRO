## [Unreleased]

### Changed
- **The module is licensed CC BY 4.0** ([#276](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/276)), not GPL-3.0: `dcterms:license` names <https://creativecommons.org/licenses/by/4.0/>. Reuse needs attribution only, so another ontology can import or extend its terms under its own licence. Earlier releases keep the licence they were released under. `LICENSING.md` says what in the repository is under which licence. No IRI, axiom or term changes.

### Changed
- **`StandaloneDrawingReference` says that an entry in a drawing index is one** ([#269](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/269)): the drawing number in a row naming a drawing is a complete reference to that drawing.
- **Every term of the module has a `skos:definition`** ([#273](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/273)): the sentence or two of its old comment that say what the term is, tagged `@en`, with the rest of the comment kept as its `rdfs:comment`. `Dimension`'s comment was only a definition, so it has no `rdfs:comment` now. `hasReferenceSymbol` and `referencesLayout` have a definition written for the property ("A ReferenceSymbol drawn on this Layout", "The target Layout that this ReferenceSymbol points to"); the meaning is unchanged. Downstream consumers that read a term's `rdfs:comment` as its definition may need adjustments.
- **The standard each reference term corresponds to is in its `rdfs:comment`** ([#272](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/272), [#262](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/262)): ISO 7519:2025 §4.3.1 and ISO 128-3:2022 §5.1 for `ReferenceExpression`; ISO 128-3:2022 §4.1, §4.12 and §6.2.1 to §6.2.4, and ISO 7519:2025 §4.3.1, for `ReferenceSymbol`; ISO 128-3:2022 §4.1 for `referencesLayout` and `LayoutIdentifierMention`; ISO 128-3:2022 Annex F, F.4 (a designation supplemented by a slash and the drawing number) for `InlineLayoutDrawingReference`; ISO 7200:2004 §5.1.3 for `DrawingIdentifierMention`, which also says that a project using its file information container ID as the drawing number may reproduce it, with the UK National Annex to BS EN ISO 19650-2:2018 (2021 revision), NA.2.2, for the composition of that ID; ISO 9431:1990 §5.2.4 and ISO 7519:2025 §4.3.1 for `StandaloneDrawingReference`, whose comment adds that an identifier standing alone being a complete reference is ADIRO's rule, not a requirement of either standard. `Grid` says that it is not the grid reference system of ISO 5457:1999 §4.4. Only clauses checked against the standard are cited.
- **The reference terms say "drawing", not "sheet"** ([#272](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/272)): "a standalone drawing-identifier reference", "drawing-identifier text", "relating layout identifier(s) to a drawing identifier", "one DrawingIdentifierMention and at least one LayoutIdentifierMention", "at most one accepted DrawingSheet" and "merge two drawings". `StandaloneDrawingReference` names the `contains` edge it does not need, instead of a property that does not exist, and states the drawing-index entry in its definition. `LayoutIdentifierMention`'s text is "a short identifier, such as a number, a letter or a sheet-grid coordinate", not only "a small integer or letter". No IRI, axiom or label changes.

### Added
- **Example images of each variety of reference** ([#269](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/269)), synthetic like the others, drawn after the shapes real drawings use, with fictional numbers, and with the reference text boxed in red in the standalone, inline and mention images (a marker image shows the marker itself): `ReferenceSymbol` a section marker on its cutting line, an elevation marker, an interior elevation marker, a detail marker with a leader and a same-drawing marker with no drawing number (`_03` to `_07`); `StandaloneDrawingReference` at a match line, in a legend, in general notes, in a schedule, in a drawing index and in a "for continuation" note (`_03` to `_08`); `InlineLayoutDrawingReference` with a single layout and drawing (`_03`); `DrawingIdentifierMention` and `LayoutIdentifierMention` inside a graphical marker (`_03`). Each of these five terms now links a redrawing of its `_01` image as `_02` in place of `_01`: the same picture, with the reference text boxed in red where it has one, and, for `ReferenceSymbol`, the section marker's arrow on its bubble, perpendicular to the cutting line, and the elevation marker's arrow pointing away from its bubble, towards the face it shows (in `ReferenceSymbol_01.png` it pointed back at the bubble). The `_01` images stay served unchanged, because released versions name them.

## [6.0.0] — 2026-11-26

### Changed
- **`denotesDrawingSheet` and `inlineReferencesLayout` have a `skos:definition`** ([#273](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/273)); the rest of each old comment stays as the `rdfs:comment`.
- **BREAKING: renamed from `adiro_common_symbols`** ([#281](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/281)). The module, its ontology IRI and the IRI of every term it defines now use `adiro_drawing_symbology` (`https://w3id.org/adiro/adiro_drawing_symbology`) instead of `adiro_common_symbols`, and the title says "ADIRO Drawing Symbology Ontology". Apart from the terms of the next entry, the terms, their definitions and their axioms are those of the old module's final release, whose version this release follows with a MAJOR bump. Every release of the old module stays published at its own IRI and is named here with `owl:priorVersion`; its history is in [its changelog](adiro_common_symbols.md), and the old module is deprecated for its final release (adiro_common_symbols 5.0.1) and stays in `src/` for one release cycle. The example images are published under the new module's path. `migration/aec_to_adiro.ttl` maps each old term IRI, from `aec_*` and from the earlier `adiro_*` module, to the new one, and `scripts/migrate_aec_to_adiro.py` rewrites a graph or a list of links. Downstream consumers may need adjustments: the annotation tooling reads the class IRIs, so every class and property of the module has a new IRI.
- **`ReferenceSymbol` specialises this module's `ReferenceExpression`** ([#277](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/277)), not the `ReferenceExpression` of `adiro_drawing_metadata`, which is equivalent to it. The meaning is unchanged, but the compatibility diff reads a new superclass IRI as a superclass change, so this module's next release is a MAJOR one.

### Added
- **The UC-03 reference terms are defined here** ([#277](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/277), with [#271](https://github.com/BuroHappoldMachineLearning/ADIRO/issues/271)): `ReferenceExpression` (the superclass of a complete reference, graphical, inline or standalone), `DrawingIdentifierMention`, `LayoutIdentifierMention`, `InlineLayoutDrawingReference` ("Inline Layout and Drawing Reference"), `StandaloneDrawingReference` ("Standalone Drawing Reference"), and the properties `denotesDrawingSheet` and `inlineReferencesLayout`. They were released in `adiro_drawing_metadata` as `ReferenceExpression`, `DrawingIdentifierMention`, `LayoutIdentifierMention`, `InlineLayoutSheetReference`, `StandaloneSheetReference`, `denotesDrawingSheet` and `inlineReferencesLayout`; those IRIs stay there, deprecated and equivalent to the new terms. The definitions, superclasses, example images (also served from this module's folder) and `isComputerVisionLabel` markers are the ones they had. `ReferenceSymbol` is now a subclass of this module's own `ReferenceExpression`. The module's introduction is widened to say it holds the reference terms.
  Downstream consumers may need adjustments: the annotation tooling takes these labels from the class IRIs, so each label is offered from this module, under the new names for the two reference classes.
